## 一、评估标尺（铁律：不许换尺）

所有策略改动的评估，一律用同一把标尺，中途不换文件、不换列：

```
文件: reports/position_overlap_audit/model3_live_candidate_8302_daily_cash_constraint.csv
指标: trade_return 列连乘 = 8,302x   |   最大回撤基准 = -18.3%
```

**为什么必须锁死**：2026-07-24 在"D 持仓要不要挡 L"上连续给出 4 个互相矛盾的结论，根因全是换标尺
（一会用 mode1 基线曲线 3,039x、一会用 8302x 文件、一会用 cash_adjusted_return 801x）。标尺一换结论就翻，
无法判断对错。锁死后这类错误结构上消失。

**8302x 的正确定位**：它是**理论对齐基准**，不是实盘可达目标。
- `trade_return` 连乘 = 8,302x = 每笔满仓的理想上界；
- `cash_adjusted_return` 连乘 = 801x = 计入衔接日现金约束后的现实值；
- 实盘还有滑点、排队买不进等执行损耗（由每晚"执行对账"单独跟踪）。

**用法**：只做**相对比较**（改动前 vs 改动后）。基准的绝对值是否可达不重要，只要基准固定，
就能量化每次改动"是好是坏、差多少"。已知偏移（如基准含 B 而实盘已删 B）在相对比较中自动抵消。

## 四、删 B 专条（2026-07-22 执行，勿引用旧的 -29%）

**方向：正确**（硬数据支撑）
- B 单笔 +1.88% 垫底，空档让给 E2（+4.41%）/ C（+3.81%）每笔多赚一倍以上；
- B 的空档**补得上**——E2 候选覆盖 402/481 天（84%）。

**幅度：算不准，不要引用任何单一数字**
| 口径 | 结果 |
|---|---|
| 零回补（悲观下界） | 4,974x（-40%） |
| "只 E2 补位"（早期算法） | 5,891x（-29%） |
| 按真实触发率回补 | 12,167x（**+47%**） |
| 全 E2 补位（乐观上界） | 13,417x（+62%） |
| OpenAI 独立测算 | 11,931x（+44%） |

**算不准的根因**：B 的 23 个成交日里 E2/C 当天到底有没有票——现有文件查不出
（`abc_detail` 与 `abce2_audit` 每天只记 1 条被选中的腿，且两文件 B 笔数不一致：23 vs 13）。

**通用判据（最重要的一条）**：
> **"单笔弱就删"不是判据，判据是"空档能不能补"。**

- **B**：空档补得上（E2 天天有票）→ 删掉净赚；
- **D**：空档**实测一笔都补不上**（19 个纯 D 日 `conflict_type` 全为 NOT_L_DAY 且 `abc_return`=0；
  D 独占 T+1 的 4 个 L 信号全不过 base 规则）→ 删掉 -54%。
- 且 D 的最大回撤区间（2024-08-02→09-05）D 交易 0 笔，**D 不增加任何风险**。
- D 价值集中在 2024（×23.3→×10.6，-55%），2025 打平，2026 微正（+2%）——2026 全年若仍如此，明年初重评。

**通用教训**：
- "关注度/人气"类信号（股吧热度、搜索量、榜单）**默认负期望**，除非与涨停结构结合（那已是现有体系）；

## 八、工作方式铁律（用户明确要求）

1. **不打补丁要根治**：出事故先做同类全景审计，一次收口；修复优先"消灭特例、统一进已有机制"；
   补丁只作临时兜底且必须附根治计划。**架构手术只在非交易日做。**
2. **同口径**：任何复利/回撤对比，必须声明用哪个文件哪一列，中途不换。
3. **非劣才改**：任何改动，复利不劣、回撤不劣才准上线；原逻辑更好就不动。
4. **结论要讲清原因**：日志/推送不能只给结论（"不开仓"），必须说明为什么（"D 持仓未到期占用资金"）。
