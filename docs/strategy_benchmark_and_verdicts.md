### 标尺必须配一份代入证明（2026-08-07 新增，铁律）

**认证脚本的复利只有在"实盘会选出同样的票"时才成立。** 单看认证脚本、单看实盘
代码，都可能各自"改好了"却合不上——2026-08-07 腿序改造只改了下游挑选顺序，
上游各信号脚本的占用门还按旧腿序拦截，认证跑 27870x、实盘只能跑 22903x，
差 17.8%，两边代码看起来都对。

所以任何改动之后，除了跑认证脚本，还必须跑：

```
python3 scripts/verify_live_engine_matches_certify.py
```

它**直接调用实盘代码**（不是复刻实盘逻辑）——真实的
`combined_live_engine.build_model3_plan` + 真实的上游门
`run_strategy_m_signal.higher_priority_leg_has_signal` /
`run_strategy_e_signal.has_ac_planned_order`——把各腿候选写成实盘平时读的
文件，让实盘自己做决定，再与认证脚本逐笔比对。资金占用与收益计算沿用认证脚本，
只替换"选哪条腿"这一环，隔离出要证明的东西。


**为什么必须锁死**：2026-07-24 在"D 持仓要不要挡 L"上连续给出 4 个互相矛盾的结论，根因全是换标尺

无法判断对错。锁死后这类错误结构上消失。

**8302x 的正确定位**：它是**理论对齐基准**，不是实盘可达目标。
- `trade_return` 连乘 = 8,302x = 每笔满仓的理想上界；
- `cash_adjusted_return` 连乘 = 801x = 计入衔接日现金约束后的现实值；
- 实盘还有滑点、排队买不进等执行损耗（由每晚"执行对账"单独跟踪）。

**用法**：8302只做历史相对比较；当前策略任何改动必须使用145笔无L逐日组合标尺，
同时验证对应单腿、完整组合、前后半段/分年方向和实盘共用规则源。

## 八、工作方式铁律（用户明确要求）

1. **不打补丁要根治**：出事故先做同类全景审计，一次收口；修复优先"消灭特例、统一进已有机制"；
   补丁只作临时兜底且必须附根治计划。**架构手术只在非交易日做。**
2. **同口径**：任何复利/回撤对比，必须声明用哪个文件哪一列，中途不换。
3. **非劣才改**：任何改动，复利不劣、回撤不劣才准上线；原逻辑更好就不动。
4. **结论要讲清原因**：日志/推送不能只给结论（"不开仓"），必须说明为什么（"D 持仓未到期占用资金"）。
