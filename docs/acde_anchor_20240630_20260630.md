# ACDE严格两年锚点、策略更新与A>C>E>D优先级落地说明

最后更新：2026-08-24

## 一、当前唯一研究锚点

- 自然日窗口：`20240630~20260630`。
- 2024-06-30为非交易日，首个可用信号日为2024-07-01。
- 当前真实开仓日组合顺序：`A>C>E>D`。
- 仓位：82.5%，单账户逐笔机械复利。
- 费用、滑点、涨跌停、T+1、跌停延期卖出、D成交压力折扣保持不变。
- 输入行情缓冲锁至2026-07-10，用于覆盖T+3和最多4个交易日的跌停延期退出检查。

旧窗口305.348870倍和五年重放343.5434倍不属于当前窗口，禁止作为候选比较基线。

## 二、新窗口底座与双门槛

新窗口应用优化前A/E排序后，底座为133笔、300.31246148623836倍，最大回撤
-23.3484%。每个排序候选必须同时满足：

1. 对应策略腿独立机械复利严格提高；
2. 只替换该腿、冻结另外三腿后，ACDE组合机械复利严格提高。

结果如下：

未做占仓去重的候选池逐笔相乘只保留作诊断，优化前D/A/E/C分别为

实际成交分腿为D=22、A=44、E=49、C=17；它不再是当前组合锚点。

## 六、A>C>E>D真实开仓日优先级与当前最终锚点

2026-08-24按用户明确决定，将生产资金顺序调整为`A>C>E>D`。正式认证不再把D和
A/C/E都压在同一信号日比较，而是使用真实资金动作日：A/C/E读取上一交易日收盘后
计划并在`buy_date`开仓；按A、C、E选择唯一静态计划；三腿均无计划时D才启动当日
盘中路径；持仓在退出日收盘后释放，退出日本身不能再开新仓。

六种可执行静态腿排序（D固定最后）中，历史复利最高的是`A>E>C>D`的
1164.500295倍；用户明确选择把C提升到E之前，并接受`A>C>E>D`复利下降。`C>A>E>D`
与`A>C>E>D`历史路径相同，但当前生产保留“A无正式候选才由C补位”的既有依赖，
因此选择改动更小的`A>C>E>D`。

## 七、实际配置变更

### A

文件：`config/strategy_config.json`

- 入选条件由单一AND改为两个冻结profile的OR，仅新增封单比例`0_3pct_0_5pct`分支。
- 顶层最终排序由`profit_source_score + turnover_rate`改为
  `profit_source_score + limit_times`，均为降序。
- C单独保存原`profit_source_score + turnover_rate`排序，禁止继承A的新排序。
- A当前版本标识为`A_FD_EXPANSION_20260630_V1`，生效日为2026-08-25。

### E

文件：`config/strategy_e_r1_scenarios.json`、`src/strategy_e.py`

- R1场景、neutral过滤、入场门禁和T+2/T+3退出不变。
- 最终排序改为信号日`turnover_rate`高值与`amount_ratio_1d`低值的50%/50%同日分位综合分。
- 并列时依次按`scenario_rank`、`ts_code`升序，保证跨平台稳定。
- 选股字段继续通过严格未来字段黑名单校验。

### D与C

D在本轮A/E排序研究中未修改，后续已经单独发布回封因子规则。C原规则在A/E阶段
曾保持不变；本次C专项研究通过双复利门槛后，正式切换为两分支OR配置。C继续使用
独立的`profit_source_score + turnover_rate`排序，不继承A的`limit_times`第二排序键。

## 八、复现命令与日志

重现本轮269个唯一排序变体：

```bash
python3 scripts/optimize_strict_acde_from_official_baseline.py --legacy-baseline
```

该命令只复现早期D>A>E>C历史底座，不是当前A>C>E>D半年优化入口。优化器会在标准错误日志中报告底座复现、各腿搜索进度、唯一变体数和双门槛结论；
完整JSON仍写到标准输出，便于脚本解析。输出：

- `reports/strict_acde_optimization/summary.json`
- `reports/strict_acde_optimization/ranking_search.csv`

复核当前配置证书：

```bash
python3 scripts/certify_strict_asof_portfolio.py
```

只有明确接受输入数据变化时才允许：

```bash
python3 scripts/certify_strict_asof_portfolio.py --refresh-input-manifest
```

当前证书必须复现A独立63笔、18.9115486868倍、E独立74笔、11.7037898965倍、
C独立55笔、23.6176160942倍，以及真实开仓日ACDE 136笔、1023.7912439628倍、
分腿A42/C47/E36/D11。详细C规则见
`docs/strategy_c.md`，本次A研究明细见`reports/strategy_a_current_window/20260630/`。

认证器日志会记录窗口、优先级、清单路径、成交数、复利、最大回撤、分腿样本和最终
fail-closed状态。

## 九、风险与发布状态

- 当前协议是`STRICT_DISCOVERY`，`release_eligible=false`。
- A/E排序来自同一窗口内多候选搜索，E双因子只改变3个信号日，存在多重比较、路径依赖和过拟合风险。
- `strict_asof_passed=true`只证明决策未使用未来数据，不代表策略已取得发布资格。
- 资金容量未认证；机械复利不是大资金可实现收益，也不代表未来收益。
- 严格历史证书只作研究统计，不参与实盘BUY开关；真实订单必须继续通过交易时间、
  资金、仓位、重复委托、成交概率、涨跌停和QMT状态等执行风控。
