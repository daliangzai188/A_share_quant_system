# ACDE严格两年锚点与A/E排序落地说明

最后更新：2026-08-21

## 一、当前唯一研究锚点

- 自然日窗口：`20240630~20260630`。
- 2024-06-30为非交易日，首个可用信号日为2024-07-01。
- 组合顺序：`D>A>E>C`。
- 仓位：82.5%，单账户逐笔机械复利。
- 费用、滑点、涨跌停、T+1、跌停延期卖出、D成交压力折扣保持不变。
- 输入行情缓冲锁至2026-07-10，用于覆盖T+3和最多4个交易日的跌停延期退出检查。

旧窗口305.348870倍和五年重放343.5434倍不属于当前窗口，禁止作为候选比较基线。

## 二、新窗口底座与双门槛

新窗口应用优化前A/E排序后，底座为133笔、300.31246148623836倍，最大回撤
-23.3484%。每个排序候选必须同时满足：

1. 对应策略腿独立机械复利严格提高；
2. 只替换该腿、冻结另外三腿后，ACDE组合机械复利严格提高。

结果如下：

| 策略腿 | 优化前独立复利 | 选中规则 | 优化后独立复利 | 单腿替换组合复利 | 结论 |
| --- | ---: | --- | ---: | ---: | --- |
| D | 2.026124倍 | 无 | 2.026124倍 | 无合格候选 | 不修改 |
| A | 10.103128倍 | `profit_source_score:desc + limit_times:desc` | 12.023750倍 | 313.116511倍 | 修改 |
| E | 4.664899倍 | `turnover_rate:desc` | 10.834162倍 | 314.325224倍 | 修改 |
| C | 3.110831倍 | 无 | 3.110831倍 | 无合格候选 | 不修改 |

表中的“独立复利”同样执行单策略、单账户占仓：上一笔未退出时不能重复使用资金。
未做占仓去重的候选池逐笔相乘只保留作诊断，优化前D/A/E/C分别为
53/69/90/46笔、3.156594/8.149269/5.948529/2.424303倍；优化后A/E候选池为
69/91笔、9.698459/15.490272倍。这些候选池数字不是可执行的独立策略复利，也不作为
双门槛的第一道判定。

A、E同时应用后为132笔、327.72671897548867倍，最大回撤-22.9705%。组合内
实际成交分腿为D=22、A=44、E=49、C=17。

## 三、实际配置变更

### A

文件：`config/strategy_config.json`

- 入选条件、T+2退出、仓位和执行模型不变。
- 顶层最终排序由`profit_source_score + turnover_rate`改为
  `profit_source_score + limit_times`，均为降序。
- C单独保存原`profit_source_score + turnover_rate`排序，禁止继承A的新排序。

### E

文件：`config/strategy_e_r1_scenarios.json`、`src/strategy_e.py`

- R1场景、neutral过滤、入场门禁和T+2/T+3退出不变。
- 最终排序改为信号日`turnover_rate`降序。
- 并列时依次按`scenario_rank`、`ts_code`升序，保证跨平台稳定。
- 选股字段继续通过严格未来字段黑名单校验。

### D与C

没有候选同时通过独立腿和组合复利门槛，规则不修改。C增加独立排序配置只是为了
防止A的顶层排序变化串入C，不是C策略优化。

## 四、复现命令与日志

重现本轮269个唯一排序变体：

```bash
python3 scripts/optimize_strict_acde_from_official_baseline.py
```

优化器会在标准错误日志中报告底座复现、各腿搜索进度、唯一变体数和双门槛结论；
完整JSON仍写到标准输出，便于脚本解析。输出：

- `reports/strict_acde_optimization/summary.json`
- `reports/strict_acde_optimization/ranking_search.csv`

复核当前配置证书：

```bash
python3 scripts/certify_strict_asof_portfolio.py
```

只有明确接受输入数据变化时才允许：

```bash
python3 scripts/certify_strict_asof_portfolio.py --refresh-input-manifest
```

认证器日志会记录窗口、优先级、清单路径、成交数、复利、最大回撤、分腿样本和最终
fail-closed状态。

## 五、风险与发布状态

- 当前协议是`STRICT_DISCOVERY`，`release_eligible=false`。
- A/E排序来自同一窗口内多候选搜索，存在多重比较和过拟合风险。
- `strict_asof_passed=true`只证明决策未使用未来数据，不代表策略已取得发布资格。
- 资金容量未认证；机械复利不是大资金可实现收益，也不代表未来收益。
- 当前证书状态为`FAIL_STRICT_RELEASE_REQUIRED`，新增BUY保持关闭；SELL、撤单和已有
  持仓退出不受影响。
