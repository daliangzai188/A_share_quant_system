# A股量化系统核心框架与策略更新框架文档

最后更新：2026-08-24

## 一、文档定位

本文是系统唯一总纲，固定当前系统的核心设计思想和半年策略更新方式，作为后续逐步
优化的共同基准。前半部分描述系统如何从数据走到候选、计划、委托、成交、持仓和
发布认证；后半部分描述策略什么时候更新、使用什么数据做决定、旧版本怎样评价以及
新版本从什么时候开始积累真正样本外。它不是某一条策略的回测说明。

后续可以优化模块实现，但不能在没有单独论证、回归和文档更新的情况下破坏本文
列出的核心不变量。若文档与代码、配置或严格认证结果发生冲突，必须立即停止新BUY，
查明口径后再恢复。

### 我们在做什么

我们不是单独寻找四条历史收益最高的曲线，而是在建设一套可以长期滚动运行的ACDE
单账户交易系统：日常按冻结版本交易，每半年在固定节点基于最新两年数据重新研究，
满足逐腿双复利门槛才更新；版本冻结后的未来半年用于真实交易并形成不可改写的前向
证据。

### 我们依据什么做决定

所有研究、更新和发布必须服从以下证据链：

```text
严格as-of数据与数据质量
    ↓
单策略单账户逐笔机械复利
    ↓
只替换一腿后的ACDE总组合机械复利
    ↓
更早6个月旁路稳健性与风险披露
    ↓
冻结版本未来6个月的真实前向样本外
    ↓
真实委托、成交、滑点、费用、回撤和容量证据
```

最近24个月是半年更新时唯一的策略选择依据；更早6个月只补充风险认识，不参与投票；
未来6个月用于执行当下选择并检验冻结版本。历史机械复利是研究证据，不是收益承诺，
也不能替代真实成交和风险数据。

## 二、核心目标

系统的目标不是让四条策略各自展示一条漂亮收益曲线，而是建立一套能够被复现、
审计和安全执行的A股单账户交易闭环：

```text
严格时点数据
    ↓
候选特征与成交可靠性
    ↓
A/C/D/E各自的策略判断
    ↓
D>A>E>C统一资金裁决
    ↓
A股规则与风险门禁
    ↓
唯一委托通道
    ↓
券商成交确认与持仓账本
    ↓
执行复盘、严格认证和发布门禁
```

系统优先级固定为：

```text
数据准确 > 时点真实 > 资金不重复 > 风控安全 > 可执行性 > 回测收益
```

## 四、七层核心架构

### 1. 数据层

数据层负责回答“在当时真实能够知道什么”，不负责决定买哪只股票。

主要职责：

- 采集日线、前复权行情、涨停池、日基本面、市场情绪和题材数据；
- 尽量包含退市股票，降低幸存者偏差；
- 保存原始数据，支持按日期补采、断点续传和重复运行；
- 对交易日期、股票代码、重复行、缺失值和异常价格进行清洗；
- 记录数据来源、可用日期和口径，禁止把晚发布数据提前到信号时点。

关键原则：

```text
原始数据不可被策略脚本反向改写。
缺失数据不能用未来数据回填。
完整口径缺失时不能静默退回宽松口径。
```

### 2. 特征与成交可靠性层

该层把原始数据转换成T日可见的市场、板块和个股特征，并评估候选是否具有现实
成交可能性。

主要内容：

- 涨停数量、跌停数量、连板数量和市场退潮状态；
- 板块涨停数量、板块情绪和题材热度；
- 首次涨停时间、炸板次数、连板高度和封单比例；
- 换手率、成交额倍率、量比和流通市值；
- 严格as-of成交空间及`fill_probability`；
- `allow_buy_reliable`、`is_fill_score_reliable`和数据质量标记。

成交概率不是收益因子，而是可执行性门禁。涨得好的股票如果历史上基本买不到，
不能按理想成交计入可执行收益。

### 3. 策略候选层

候选层只回答“各策略按自己的规则看中了谁”，不应自行分配组合资金。

当前四条腿的角色：

| 策略 | 当前角色 | 主要时点 |
|---|---|---|
| D | 盘中首板回封策略，组合最高优先级 | 09:30起记录路径，14:00后允许BUY |
| A | 收盘主策略，偏低热度环境的综合得分与连板高度排序 | T日收盘 |
| E | 40条R1场景并集、板块neutral、换手率降序 | T日收盘 |
| C | 两条强势/龙头子风格OR，A无正式选中时生成计划、组合中低于E | T日收盘 |

必须区分以下对象：

```text
候选：策略规则筛选后的股票。
第一候选：该策略内部排序后的第一名。
正式信号：通过策略自身门禁、允许进入组合裁决的信号。
计划单：组合层分配资金后生成的待执行计划。
委托：已经提交到券商的订单。
成交：券商确认的真实成交数量和价格。
持仓：成交确认后写入统一持仓账本的资产。
```

候选不等于正式信号，正式信号不等于计划单，计划单不等于委托，委托也不等于
成交。日志和报告不得混用这些概念。

当前实现中，存在任何未平仓持仓、A已有计划或D当日已成交时，E不会生成正式信号，
但会执行只读候选检查并记录候选数和第一名。这解决了“E没有候选”和“E没有计算”
无法区分的问题，但也说明当前候选生成与资金优先级尚未完全解耦，属于后续可优化项。

### 4. 组合资金裁决层

组合层是整个系统的核心。四条策略不能各自拥有一份独立资金，最终必须进入同一个
单账户状态机。

固定裁决顺序：

```text
券商/本地仍有策略持仓
    → 禁止任何新开仓

账户确认空仓
    → D已成交或占用资金：其余腿不买
    → 否则A有正式计划：选择A
    → 否则E有正式计划：选择E
    → 否则C有正式计划：选择C
    → 全部没有：保持空仓
```

核心不变量：

- 每天最多形成一个实际开仓方向；
- 上一笔未退出前不得复用同一资金；
- 低优先级策略执行失败后不能擅自切换为过期的其他策略计划；
- 展示层可以列出所有候选，但不得重新解释优先级或参与下单；
- 理论计划与券商真实持仓冲突时，以经过完整性认证的券商状态为准；
- 状态未知时保持空仓，不做乐观推断。

### 5. 交易执行层

执行层只负责把组合层已经批准的唯一计划安全地送到市场，不负责重新选股。

必须执行的检查：

- 是否为交易日和允许的交易时段；
- 是否已有持仓、未完成委托或同票风险暴露；
- 是否超过82.5%目标仓位、85%硬顶或单笔限额；
- 是否满足最小成交可靠性和退出容量限制；
- 是否违反T+1；
- 涨停是否可以买入、跌停是否可以卖出；
- 是否存在重复订单、陈旧计划或过期执行窗口；
- 严格发布证书是否允许新BUY。

所有真实订单必须经过唯一券商适配器和统一下单网关。策略脚本、播报脚本和研究
脚本不得绕过网关直接下单。

### 6. 成交、持仓与恢复层

系统资金状态必须由真实成交驱动，而不是由“下单成功”或“计划生成成功”驱动。

核心流程：

```text
提交委托
    ↓
查询订单状态与真实成交量
    ↓
按成交分片写入持仓账本
    ↓
生成T+1可卖日期和计划退出日期
    ↓
到期平仓、撤单、残单补挂
    ↓
再次以券商余仓确认是否真正清空
```

恢复原则：

- daemon重启后先恢复券商连接和状态，不盲目补单；
- 本地账本缺失时只能依据经过完整性校验的券商快照恢复；
- 单轮查询异常不能直接把本地持仓标记为已清空；
- 未知成交数量按可能占用资金处理；
- D缺少09:30起完整盘中路径时，不能用午后快照伪造可交易信号；
- 状态文件损坏、分歧或版本落后时必须修复或fail-closed。

### 7. 审计、回测与发布层

研究结果和实盘发布是两个不同阶段。

严格回测必须同时满足：

- 信号只使用当时可见数据；
- 单账户占仓期间不重复使用资金；
- 统一费用、滑点、涨跌停和T+1规则；
- 候选池指标、独立策略指标和组合实际成交指标分开报告；
- 输入文件、代码文件和配置文件可哈希复现；
- 规则变化后从锁定底座逐腿替换，不能混用旧口径。

当前发布门禁：

```text
strict_asof_passed=true
并不等于
release_eligible=true
```

只有完成冻结样本外、walk-forward、容量验证、连续模拟盘和发布复核后，才能考虑
解除新BUY门禁。SELL、撤单和已有持仓退出不应被新BUY门禁阻断。

## 五、日常运行闭环

### 收盘流水线

```text
采集数据
→ 清洗合并
→ 市场/板块特征
→ 成交概率打分
→ 增强因子
→ A/C候选与计划
→ E候选/信号状态
→ 健康度和执行审计
→ ACDE候选产物只读统计
→ 组合计划播报
```

收盘候选统计只读取当日产物，不重新运行策略、不改变`D>A>E>C`、不生成委托。
产物缺失必须显示“未知”，不能误报为“候选0只”。

### 次日执行

```text
启动恢复与持仓核对
→ 组合状态机读取当日有效计划
→ 盘前容量和价格复核
→ 竞价/开盘执行
→ 成交确认与残单处理
→ 盘中D状态与持仓监控
→ 到期平仓和收盘看门狗
→ 执行完成率、滑点和真实收益复盘
```

## 六、核心安全不变量

以下规则属于框架级约束，不得因单次回测收益提高而绕过：

1. 禁止未来函数和结果字段参与选股。
2. 禁止候选池逐笔相乘冒充独立单账户复利。
3. 禁止四条策略分别假设拥有同一份完整资金。
4. 禁止持仓未确认清空时开新仓。
5. 禁止把委托受理当成真实成交。
6. 禁止涨停默认买入、跌停默认卖出。
7. 禁止T日买入后T日卖出。
8. 禁止过期计划在错过窗口后追补。
9. 禁止策略脚本绕过统一下单网关。
10. 禁止数据、证书或状态未知时乐观放行。
11. 禁止用旧窗口或旧输入哈希替代当前严格锚点。
12. 禁止把`STRICT_DISCOVERY`结果描述为可发布实盘收益。

## 七、当前已知短板

### 1. 研究与过拟合风险

A和E的新排序来自当前两年窗口内269个唯一排序变体搜索。虽然通过了“独立腿复利
提高”和“只替换该腿时组合复利提高”的双门槛，但仍属于同窗口发现，缺少真正冻结
后的前向样本外证据。

### 2. 候选层与资金层仍有耦合

理想结构应当是每条策略先独立输出不可变候选/正式信号，再由组合层统一分配资金。
当前E在A、D或持仓占用时只计算只读候选，不生成正式信号，审计信息已经补齐，但
架构边界仍不完全纯粹。

### 3. 守护进程职责过重

`scripts/trading_daemon.py`同时承担调度、播报、状态恢复、组合计划、成交确认、持仓
同步和推送。功能完整，但修改影响面较大，是当前主要维护风险。

### 4. 真实成交与容量证据不足

集合竞价、分钟成交、盘口排队、极端涨跌停、资金规模变化和连续模拟盘尚未形成完整
认证闭环。当前机械复利不能直接外推到真实大资金。

### 5. 数据源与恢复仍需增强

核心策略仍高度依赖Tushare及本地缓存。需要继续完善多源核验、字段漂移告警、交易日
完整性检查和可恢复的数据版本管理。

## 八、策略更新框架

### 1. 更新目标

策略更新框架解决四个问题：什么时候更新、使用哪段数据做决定、旧版本怎样封存、
新版本从什么时候开始积累真正样本外。它不改变前文的数据、单账户资金、A股交易规则
和统一执行安全不变量。

完整半年循环为：

```text
每半年到达固定节点
    ↓
先封存旧版本过去半年的真实前向表现
    ↓
使用截至节点的最近24个月寻找并决定新规则
    ↓
用24个月之前的更早6个月做只读旁路验证
    ↓
冻结新版本
    ↓
在未来6个月按新版本交易并积累真正前向样本外
```

### 2. 固定更新时间

每年只在以下两个自然日进入正式策略更新流程：

- `6月30日`
- `12月31日`

若节点日不是交易日，窗口仍以该自然日为截止日，数据取不晚于截止日的最后一个可用
交易日。不能因为短期回撤、连续亏损、行情突然变热或某个候选表现突出而在半年中途
重新调参。

半年内允许修复数据错误、程序缺陷和执行安全问题，但必须区分：

- **行为不变修复**：不改变历史候选、买卖日期、仓位和资金顺序，可按工程流程修复；
- **策略行为变化**：会改变候选、排序、过滤、持有期、腿序或仓位，只能进入下一个
  `6月30日/12月31日`更新节点评审。

### 3. 三个时间窗口

设本轮更新时间为`T`，三个窗口严格定义如下：

| 窗口 | 日期范围 | 用途 | 是否影响本轮策略决策 |
|---|---|---|---|
| 更早6个月旁路验证 | `T-30个月 <= 信号日 < T-24个月` | 检查新规则在更早市场环境中的稳定性 | 否 |
| 最近24个月决策窗口 | `T-24个月 <= 信号日 <= T` | 寻找规则、比较候选、决定是否更新 | 是，且是唯一决策窗口 |
| 未来6个月前向样本外 | `T < 信号日 <= T+6个月` | 按冻结新版本真实交易并观察 | 不反向修改已冻结版本 |

三个窗口的角色不能互换，也不能把最近24个月改成“前18个月寻找规则、后6个月决定
是否通过”。最近24个月是一个完整的滚动决策窗口，全部用于寻找并决定当下最佳策略。

#### 最近24个月：寻找和决定规则

在每个半年节点，A、C、D、E都使用截至该节点的最近24个月严格数据重新研究。该窗口
同时承担规则发现和本轮策略决策，不额外从其中扣出6个月作为否决型验证集。

研究时继续锁定以下组合口径：

- 严格as-of，只使用信号时点可见的数据；
- 单账户逐笔机械复利；
- `D>A>E>C`资金占用顺序；
- 82.5%目标仓位；
- 费用、滑点、涨跌停、停牌和T+1规则；
- 一次只替换一条腿，另外三条腿冻结为本轮起始基线；
- 只有候选策略的独立单账户复利和逐腿替换后的总组合复利都严格提高，才允许修改
  该策略；否则保持旧规则。

D腿允许在半年节点把信号时点字段离散为固定因子值，并枚举多条`AND`条件分支。
每条分支必须先达到冻结的样本数、平均收益和胜率门槛，然后逐条独立替换当前D并
执行完整ACDE回放。只有D独立复利和ACDE总复利都提高的分支才进入最终排名，再取
ACDE复利最高的一条作为人工审核候选；全部条件`OR`只保留为诊断，不作为发布规则。
当前实现与结果见
[策略D半年多因子逐组合双门选优框架](strategy_d_factor_union_optimizer.md)。

所有候选必须从同一节点、同一24个月窗口的旧版本基线逐腿替换比较，禁止混用旧窗口
倍数、五年底座或其他资金口径。

#### 更早6个月：只读旁路验证

最近24个月之前的更早6个月用于观察规则跨市场阶段的表现，但它不是本轮策略决策
窗口，也不能改变最近24个月已经得出的选择。

该窗口只回答：

- 新规则放到更早一段行情中，交易方向是否明显异常；
- 收益是否完全依赖最近24个月中的单一行情阶段；
- 回撤、连续亏损、盈亏比和成交可行性是否暴露额外风险；
- 是否需要在报告中提高风险提示或降低对研究结论的信心。

固定约束：

- 旁路结果不能否决最近24个月的双复利决策；
- 旁路结果不能触发继续调参、增加过滤条件或回到24个月窗口重新搜索；
- 不能挑选更早6个月中表现好的参数替换本轮结果；
- 必须原样披露正面和负面结果。

因为规则是在时间上更晚的24个月数据中找到，再回放到更早6个月，所以这段只能称为
**更早历史旁路验证**，不能冒充真正的前向样本外。它的价值是补充稳健性观察，而不是
取得发布资格或预测未来收益。

#### 未来6个月：真正前向样本外与交易期

在节点`T`完成研究后，必须先冻结新版本的策略规则、配置、数据清单、代码哈希、组合
顺序和认证结果。冻结完成后，从`T`之后第一个交易日起到下一更新节点，按该版本进行
实际交易；这未来6个月才是本版本真正的前向样本外。

要把这6个月称为真正前向样本外，必须同时满足：

- 第一个前向信号产生前已经完成版本冻结；
- 半年内不根据新出现的收益、回撤或候选修改策略参数；
- 每日候选、正式信号、组合选择、委托、成交和持仓结果完整留档；
- 费用、滑点、涨跌停、T+1和实际成交约束继续执行；
- 数据修复不得事后改写当日已经形成的候选结论；
- 实盘结果只描述已经发生的交易，不承诺未来收益。

未来6个月是新策略的实际使用期，不是等待验证结束后才启用策略。本轮按最近24个月
得到的最新最佳版本，会在下一半年直接投入受现有认证、风控和资金限制约束的交易；
到下一个更新节点，再先封存这段表现。

### 4. 逐腿更新决策

本轮每条策略只允许出现两种正式结论：

1. `UPDATE`：最近24个月中，候选规则的独立策略复利严格高于旧规则，并且只替换该腿
   后的ACDE总组合复利也严格高于旧组合；全部严格口径一致。
2. `KEEP_CURRENT`：上述任一条件不满足、数据不完整、口径不一致或无法严格复现，
   该策略保持不变。

更早6个月的旁路验证单独给出`STABLE / RISK_WARNING / INSUFFICIENT_DATA`，只影响
风险说明，不把`UPDATE`改成`KEEP_CURRENT`，也不把`KEEP_CURRENT`改成`UPDATE`。

更新A、C、D、E时必须逐腿独立判断，不能用“A和E同时替换后的组合更高”掩盖其中
某一条腿单独替换后不增益。所有腿完成后，可以再报告同时应用全部通过项的组合结果，
但它不能替代逐腿门槛。

### 5. 半年循环与版本身份

每个版本按以下顺序流转：

```text
旧版本运行满本周期
    ↓
到达6月30日或12月31日
    ↓
先冻结旧版本本周期前向样本外账本
    ↓
最近24个月滚动到当前节点
    ↓
逐腿研究ACDE并执行独立腿+总组合双复利门槛
    ↓
更早6个月只读旁路回放并披露风险
    ↓
冻结新版本身份和全部口径
    ↓
未来6个月按新版本交易
```

本周期刚完成的未来6个月，在下个节点会自然进入新的最近24个月决策窗口。这不等于
篡改上一版本的样本外结果：上一版本的账本已经永久封存；同一批日期只是从“上一版本
的前向评价数据”转为“下一轮滚动研究可使用的历史数据”，两种身份必须由版本号和
研究节点明确区分。

### 6. 永久样本外账本

每到更新节点，顺序必须是“先记旧账，再做新研究”。旧版本未完成封存时，不应启动
新一轮正式参数搜索。

每个版本的半年账本至少永久保留：

| 类别 | 必留字段 |
|---|---|
| 版本身份 | 发布编号、冻结时间、基线提交、配置/代码/输入哈希 |
| 时间口径 | 研究节点、最近24个月窗口、更早6个月窗口、未来交易期 |
| 组合口径 | 腿序、仓位、费用、滑点、T+1、涨跌停和成交规则 |
| 分策略表现 | A/C/D/E各自样本数、胜率、平均/中位数收益、复利、最大回撤、盈亏比、最大盈亏、连续亏损 |
| 总组合表现 | 实际占仓笔数、逐笔复利、最大回撤、资金占用和分腿成交数 |
| 执行质量 | 候选覆盖率、计划数、委托数、成交率、部分成交、滑点、费用、无法买卖次数 |
| 数据质量 | 缺失日、未运行、未知状态、重复记录、回填记录和异常说明 |

永久保留的含义是：

- 新版本不得覆盖旧版本记录；
- 同一发布编号和同一半年节点重复生成时，内容一致只能幂等返回；
- 内容不一致必须报冲突，不能静默用新结果替换旧结果；
- 如发现历史记录错误，只能追加更正记录并保留原记录及更正原因；
- 账本、版本清单和摘要应进入版本控制及运行状态备份。

### 8. 当前落地边界

本节现在只固定框架依据，尚未新增半年冻结脚本或研究门禁，也没有修改ACDE优化器、
策略参数、`D>A>E>C`、82.5%仓位、实盘开关、发布状态或券商流程。后续落地必须一次
只实现一个独立环节，并在每项完成、测试和提交后，先说明下一项是否值得做及其影响，
再由人工决定是否继续。

## 九、后续优化顺序

后续优化必须一次只解决一类问题，建议按以下顺序推进：

### 阶段一：候选、信号、资金裁决彻底分层

- 为ACDE定义统一、不可变的候选和正式信号结构；
- 每条策略独立记录是否完成计算、候选数量和第一名；
- 组合层只消费正式信号，不参与候选生成；
- 展示层只读取结果，不影响组合状态。

### 阶段二：拆分守护进程

- 数据流水线调度；
- 策略信号服务；
- 组合资金状态机；
- 订单执行与成交确认；
- 持仓恢复与审计播报。

每拆一层都必须保持现有行为回归一致，不能同时修改策略规则。

### 阶段三：强化数据血缘

- 为每日策略输入生成清单和哈希；
- 对关键字段建立跨数据源校验；
- 明确每个字段的最早可用时点；
- 把“0只候选”“未运行”“读取失败”“数据不完整”分别编码。

### 阶段四：补齐真实执行模型

- 集合竞价真实成交率；
- 09:30后分钟级滑点；
- 涨停排队与开板回封成交概率；
- 跌停延期卖出和尾盘容量；
- 不同资金规模下的成交覆盖率和冲击成本。

### 阶段五：冻结样本外与发布认证

- 冻结ACDE规则和配置哈希；
- 按每年6月30日、12月31日执行半年更新；
- 最近24个月作为唯一规则搜索和更新决策窗口，不拆成18个月研究加6个月否决验证；
- 24个月之前的更早6个月只做旁路稳健性观察，不反向影响本轮决策；
- 新版本冻结后的未来6个月用于实际交易并积累真正前向样本外；
- 永久保留每个发布版本的半年样本外账本；
- 连续模拟盘验证；
- 达到发布标准后再讨论小资金实盘。

## 十、框架优化的验收规则

每一次框架优化都必须回答：

1. 修改的是数据、候选、组合、执行、持仓还是认证层？
2. 是否改变任何策略的入选股票或交易时点？
3. 是否改变`D>A>E>C`、82.5%仓位或单账户占仓？
4. 是否新增未来数据、乐观成交或资金重复使用？
5. 旧行为如何回归，新行为如何单测？
6. 是否需要重跑严格认证或刷新输入清单？
7. 失败时是否仍保持fail-closed？
8. 日志能否区分未知、未运行、0候选、计划、委托和成交？

如果一次修改同时改变策略条件、资金状态机和执行模型，应拆成多个独立阶段，分别
验证和提交，避免无法判断收益或风险变化来自哪里。

## 十二、当前结论

当前框架已经具备较完整的研究、组合资金、A股规则、订单安全和审计骨架。下一阶段
不应继续优先追求同窗口回测倍数，而应围绕以下三件事逐步提高系统质量：

```text
分层更清楚
真实成交证据更多
样本外发布标准更严格
```

本文作为后续框架优化的起点。每完成一个阶段，都应更新对应章节、测试证据和发布
状态，确保系统演进始终可解释、可回退、可复现。
