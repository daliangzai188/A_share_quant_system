# A股量化系统核心框架与策略更新框架文档

最后更新：2026-09-01

## 一、文档定位

本文是系统唯一总纲，固定当前系统的核心设计思想和月度滚动策略更新方式，作为后续逐步
优化的共同基准。前半部分描述系统如何从数据走到候选、计划、委托、成交、持仓和
发布认证；后半部分描述策略什么时候更新、使用什么数据做决定、旧版本怎样评价以及
新版本从什么时候开始积累真正样本外。它不是某一条策略的回测说明。

后续可以优化模块实现，但不能在没有单独论证、回归和文档更新的情况下破坏本文
列出的核心不变量。若文档与代码、配置或严格认证结果发生冲突，必须立即停止新BUY，
查明口径后再恢复。

### 我们在做什么

我们要在真实、可复现、可执行的约束内寻找`A>C>E>D`单账户组合复利最高的量化规则，
并把它建设成可以长期滚动运行的ACDE系统：月中按冻结版本交易，每个自然月最后一个
交易日收盘并完成数据质检后，使用截至该节点的最新3年数据重新研究，结果只用于预测
紧接着的下一个自然月。下个月实际发生的候选、委托、成交和收益构成本次版本不可改写
的真正前向证据。

### 我们依据什么做决定

所有研究、更新和发布必须服从以下证据链：

```text
严格as-of数据与数据质量
    ↓
可量化因子与研究/回测/执行逻辑对齐
    ↓
全部合格候选按A>C>E>D逐笔机械回放
    ↓
按最近3年组合期末复利选择唯一第一名
    ↓
完整披露单腿、样本、回撤、异常、压力测试和过拟合
    ↓
人工审核、独立认证、冻结版本和下个月真实前向证据
```

最近3年是月度更新时唯一的候选生成、参数选择和收益排序窗口。更早数据只能做历史风险
诊断、制度差异检查和数据质量核验，不得参与当月选参或冒充独立样本外。下一个自然月
用于执行人工确认后的冻结版本并检验前向表现。历史机械复利是研究证据，不是收益承诺，
也不能替代真实成交和风险数据；但在数据、回测和逻辑均通过时，风险诊断不得把组合
复利第一名改成收益更低的候选。

## 二、核心目标

系统的目标不是让四条策略各自展示一条漂亮收益曲线，而是建立一套能够被复现、
审计和安全执行的A股单账户交易闭环：

```text
严格时点数据
    ↓
候选特征与成交可靠性
    ↓
A/C/D/E各自的策略判断
    ↓
A>C>E>D真实开仓日统一资金裁决
    ↓
A股规则与风险门禁
    ↓
唯一委托通道
    ↓
券商成交确认与持仓账本
    ↓
执行复盘、严格认证和发布门禁
```

研究选优优先级固定为：

```text
因子可量化 + 数据准确且无未来信息 + 回测成功可复现 + 逻辑完全对齐
    > 最近3年A>C>E>D组合期末复利最高
```

样本、最大回撤、盈亏比、连续亏损、容量、压力测试、过拟合和前向表现必须完整披露，
但不参与改变收益冠军的排序。真实资金执行仍按另一条安全优先级：合规与交易规则、
统一下单风控、模拟和小资金验证、用户明确授权，均不得因历史高收益而绕过。

### 组合腿序长期标准

从2026-08-24起，`A>C>E>D`不仅是当前生产配置，也是后续策略研究、参数优化、
组合回放、发布认证和实盘执行必须共同遵守的标准腿序：

```text
A：第一顺位，低分段热度、中等连板环境、适中封单比例的主策略
C：第二顺位，强势环境与龙头形态的补充策略
E：第三顺位
D：第四顺位，仅前三条静态计划均不存在时启动盘中路径
```

A优先的依据是规则更简单、数据挖掘程度相对较低、市场拥挤度较低；A按T+2退出，
C第1/2分支按T+3退出、第3分支按T+2退出，属于模型稳健性和执行风险优先；不能把它误写成“A的历史最大回撤小于
C”。当前两年窗口内A最大回撤为-19.37%、最大单笔亏损为-11.85%，均差于C的
-6.57%和-5.83%。C虽然窗口内指标更好，但三类逻辑分支来自较大的同窗口搜索空间，
前向样本仍不足，因此作为第二顺位的强势环境补充。

以后所有优化必须满足以下不变量：

1. 候选方案和基准方案都按真实`action_date`及`A>C>E>D`回放，禁止按`signal_date`
   同日重排；
2. A/C/E使用上一交易日收盘后冻结的计划，D只有在当日不存在A/C/E计划时才允许启动；
3. 按各腿真实退出日计算资金占用，退出日收盘前不得重复使用资金；
4. 优化某一腿时，其他三腿、腿序、仓位、费用、滑点、T+1及涨跌停规则全部冻结；
5. 同时报告该腿独立指标和只替换该腿后的组合指标，不能只用独立复利或候选池复利发布；
6. 其他腿序只能作为诊断材料，不得成为参数选择、版本发布或实盘切换依据；
7. 普通因子、阈值、排序、过滤或退出优化无权改变腿序。只有用户以后明确推翻本标准，
   并完成单独的顺序研究、风险接受、代码回归、认证和文档更新，才可建立新标准。

## 四、七层核心架构

### 1. 数据层

数据层负责回答“在当时真实能够知道什么”，不负责决定买哪只股票。

主要职责：

- 采集日线、前复权行情、涨停池、日基本面、市场情绪和题材数据；
- 尽量包含退市股票，降低幸存者偏差；
- 保存原始数据，支持按日期补采、断点续传和重复运行；
- 对交易日期、股票代码、重复行、缺失值和异常价格进行清洗；
- 记录数据来源、可用日期和口径，禁止把晚发布数据提前到信号时点。

关键原则：

```text
原始数据不可被策略脚本反向改写。
缺失数据不能用未来数据回填。
完整口径缺失时不能静默退回宽松口径。
```

### 2. 特征与成交可靠性层

该层把原始数据转换成T日可见的市场、板块和个股特征，并评估候选是否具有现实
成交可能性。

主要内容：

- 涨停数量、跌停数量、连板数量和市场退潮状态；
- 板块涨停数量、板块情绪和题材热度；
- 首次涨停时间、炸板次数、连板高度和封单比例；
- 换手率、成交额倍率、量比和流通市值；
- 严格as-of成交空间及`fill_probability`；
- `allow_buy_reliable`、`is_fill_score_reliable`和数据质量标记。

成交概率不是收益因子，而是可执行性门禁。涨得好的股票如果历史上基本买不到，
不能按理想成交计入可执行收益。

### 3. 策略候选层

候选层只回答“各策略按自己的规则看中了谁”，不应自行分配组合资金。

当前四条腿的角色：

| 策略 | 当前角色 | 主要时点 |
|---|---|---|
| A | 第一顺位收盘主策略，偏低热度环境的综合得分与连板高度排序 | T日收盘 |
| C | 第二顺位，两条强势/龙头子风格OR，A无正式选中时补位 | T日收盘 |
| E | 第三顺位，40条R1场景并集、板块neutral、换手率高值+封单比例低值等权分位评分；弱收益联合区间直接空仓 | T日收盘 |
| D | 第四顺位盘中首板回封策略，仅A/C/E均无计划时启动 | 09:30起记录路径，14:00后允许BUY |

必须区分以下对象：

```text
候选：策略规则筛选后的股票。
第一候选：该策略内部排序后的第一名。
正式信号：通过策略自身门禁、允许进入组合裁决的信号。
计划单：组合层分配资金后生成的待执行计划。
委托：已经提交到券商的订单。
成交：券商确认的真实成交数量和价格。
持仓：成交确认后写入统一持仓账本的资产。
```

候选不等于正式信号，正式信号不等于计划单，计划单不等于委托，委托也不等于
成交。日志和报告不得混用这些概念。

当前实现必须让A/C/E分别生成并冻结自己的上一交易日收盘计划；组合层再按固定顺序
裁决。存在任何未平仓持仓或高顺位冻结计划时，低顺位不得获得资金。D只有确认当日
A/C/E均无冻结计划后才允许启动盘中路径。候选计算、正式计划和资金裁决必须分别留痕，
从而区分“没有候选”“未完成计算”和“有候选但被高顺位或持仓阻挡”。

### 4. 组合资金裁决层

组合层是整个系统的核心。四条策略不能各自拥有一份独立资金，最终必须进入同一个
单账户状态机。

固定裁决顺序：

```text
券商/本地仍有策略持仓
    → 禁止任何新开仓

账户确认空仓
    → A有冻结计划：只处理A；即使A未成交，也不得改选当日C/E/D
    → 否则C有冻结计划：只处理C；即使C未成交，也不得改选当日E/D
    → 否则E有冻结计划：只处理E；即使E未成交，也不得改选当日D
    → A/C/E均无冻结计划：才允许D启动盘中路径
    → D未触发或未成交：保持空仓
```

核心不变量：

- 每天最多形成一个实际开仓方向；
- 上一笔未退出前不得复用同一资金；
- 低优先级策略执行失败后不能擅自切换为过期的其他策略计划；
- 展示层可以列出所有候选，但不得重新解释优先级或参与下单；
- 理论计划与券商真实持仓冲突时，以经过完整性认证的券商状态为准；
- 状态未知时保持空仓，不做乐观推断。

### 5. 交易执行层

执行层只负责把组合层已经批准的唯一计划安全地送到市场，不负责重新选股。

必须执行的检查：

- 是否为交易日和允许的交易时段；
- 是否已有持仓、未完成委托或同票风险暴露；
- 是否超过82.5%目标仓位、85%硬顶或单笔限额；
- 是否满足最小成交可靠性和退出容量限制；
- 是否违反T+1；
- 涨停是否可以买入、跌停是否可以卖出；
- 是否存在重复订单、陈旧计划或过期执行窗口；
- 严格发布证书是否允许新BUY。

所有真实订单必须经过唯一券商适配器和统一下单网关。策略脚本、播报脚本和研究
脚本不得绕过网关直接下单。

### 6. 成交、持仓与恢复层

系统资金状态必须由真实成交驱动，而不是由“下单成功”或“计划生成成功”驱动。

核心流程：

```text
提交委托
    ↓
查询订单状态与真实成交量
    ↓
按成交分片写入持仓账本
    ↓
生成T+1可卖日期和计划退出日期
    ↓
到期平仓、撤单、残单补挂
    ↓
再次以券商余仓确认是否真正清空
```

恢复原则：

- daemon重启后先恢复券商连接和状态，不盲目补单；
- 本地账本缺失时只能依据经过完整性校验的券商快照恢复；
- 单轮查询异常不能直接把本地持仓标记为已清空；
- 未知成交数量按可能占用资金处理；
- D缺少09:30起完整盘中路径时，不能用午后快照伪造可交易信号；
- 状态文件损坏、分歧或版本落后时必须修复或fail-closed。

### 7. 审计、回测与发布层

研究结果和实盘发布是两个不同阶段。

严格回测必须同时满足：

- 信号只使用当时可见数据；
- 单账户占仓期间不重复使用资金；
- 统一费用、滑点、涨跌停和T+1规则；
- 候选池指标、独立策略指标和组合实际成交指标分开报告；
- 输入文件、代码文件和配置文件可哈希复现；
- 规则变化后从锁定底座逐腿替换，不能混用旧口径。

当前发布门禁：

```text
strict_asof_passed=true
并不等于
release_eligible=true
```

通过因子量化、数据有效、回测成功可复现和逻辑对齐后，组合复利第一名可以被认定为
“可落地研究策略”；经用户审核与独立重算认证后，可以写入正式策略配置并进入模拟盘或
下个月冻结前向验证。解除真实资金新BUY仍需用户单独授权，并先做模拟、小资金和执行风控
验证；SELL、撤单和已有持仓退出不应被新BUY门禁阻断。

## 五、日常运行闭环

### 收盘流水线

```text
采集数据
→ 清洗合并
→ 市场/板块特征
→ 成交概率打分
→ 增强因子
→ A/C候选与计划
→ E候选/信号状态
→ 健康度和执行审计
→ ACDE候选产物只读统计
→ 组合计划播报
```

收盘候选统计只读取当日产物，不重新运行策略、不改变`A>C>E>D`、不生成委托。
产物缺失必须显示“未知”，不能误报为“候选0只”。

### 次日执行

```text
启动恢复与持仓核对
→ 组合状态机读取当日有效计划
→ 盘前容量和价格复核
→ 竞价/开盘执行
→ 成交确认与残单处理
→ 盘中D状态与持仓监控
→ 到期平仓和收盘看门狗
→ 执行完成率、滑点和真实收益复盘
```

## 六、核心安全不变量

以下规则属于框架级约束，不得因单次回测收益提高而绕过：

1. 禁止未来函数和结果字段参与选股。
2. 禁止候选池逐笔相乘冒充独立单账户复利。
3. 禁止四条策略分别假设拥有同一份完整资金。
4. 禁止持仓未确认清空时开新仓。
5. 禁止把委托受理当成真实成交。
6. 禁止涨停默认买入、跌停默认卖出。
7. 禁止T日买入后T日卖出。
8. 禁止过期计划在错过窗口后追补。
9. 禁止策略脚本绕过统一下单网关。
10. 禁止数据、证书或状态未知时乐观放行。
11. 禁止用旧窗口或旧输入哈希替代当前严格锚点。
12. 禁止把`STRICT_DISCOVERY`结果描述为可发布实盘收益。

## 七、当前已知短板

### 1. 研究与过拟合风险

A和E的新排序来自当前两年窗口内269个唯一排序变体搜索。虽然通过了“独立腿复利
提高”和“只替换该腿时组合复利提高”的双门槛，但仍属于同窗口发现，缺少真正冻结
后的前向样本外证据。

### 2. 候选层与资金层仍有耦合

理想结构应当是每条策略先独立输出不可变候选/正式信号，再由组合层统一分配资金。
当前E在A、D或持仓占用时只计算只读候选，不生成正式信号，审计信息已经补齐，但
架构边界仍不完全纯粹。

### 3. 守护进程职责过重

`scripts/trading_daemon.py`同时承担调度、播报、状态恢复、组合计划、成交确认、持仓
同步和推送。功能完整，但修改影响面较大，是当前主要维护风险。

### 4. 真实成交与容量证据不足

集合竞价、分钟成交、盘口排队、极端涨跌停、资金规模变化和连续模拟盘尚未形成完整
认证闭环。当前机械复利不能直接外推到真实大资金。

### 5. 数据源与恢复仍需增强

核心策略仍高度依赖Tushare及本地缓存。需要继续完善多源核验、字段漂移告警、交易日
完整性检查和可恢复的数据版本管理。

### 0-A. 历史半年框架（已废止，仅供旧报告审计）

本节以下至第八章结束的半年循环、`6月30日/12月31日`节点、最近2年确认、最近半年
否决和未来6个月等内容，均为2026-09-01以前的历史规范。它们只用于复现旧版本和旧
证书，不再约束新的策略研究、参数选择或发布时间表；如与上面的月度标准冲突，以上面
的月度标准为准。

### 1. 更新目标

策略更新框架解决四个问题：什么时候更新、使用哪段数据做决定、旧版本怎样封存、
新版本从什么时候开始积累真正样本外。它不改变前文的数据、单账户资金、A股交易规则
和统一执行安全不变量。

完整半年循环为：

```text
每半年到达固定节点
    ↓
先封存旧版本过去半年的真实前向表现
    ↓
使用截至节点的最近3年筛选、排序并决定唯一候选
    ↓
用重叠的最近2年确认近期适应性
    ↓
用重叠的最近半年只检查唯一候选是否已经失效
    ↓
人工审核、独立冻结、发布认证和显式切换
    ↓
通过则在未来6个月按新版本交易并积累前向样本外；未通过则继续旧版本
```

### 2. 固定更新时间

每年只在以下两个自然日进入正式策略更新流程：

- `6月30日`
- `12月31日`

若节点日不是交易日，窗口仍以该自然日为截止日，数据取不晚于截止日的最后一个可用
交易日。不能因为短期回撤、连续亏损、行情突然变热或某个候选表现突出而在半年中途
重新调参。

半年内允许修复数据错误、程序缺陷和执行安全问题，但必须区分：

- **行为不变修复**：不改变历史候选、买卖日期、仓位和资金顺序，可按工程流程修复；
- **策略行为变化**：会改变候选、排序、过滤、持有期、腿序或仓位，只能进入下一个
  `6月30日/12月31日`更新节点评审。

### 3. 三个时间窗口

设本轮更新时间为`T`，三个窗口严格定义如下：

| 窗口 | 日期范围 | 用途 | 是否影响本轮策略决策 |
|---|---|---|---|
| 最近3年主优化 | `T-3年 < action_date <= T` | 寻找规则、比较候选并形成唯一排名 | 是，且是唯一候选排序窗口 |
| 最近2年近期确认 | `T-2年 < action_date <= T` | 确认主窗口胜者未被较旧行情拖累 | 只做必要确认，不得重新排名 |
| 最近半年失效检查 | `T-6个月 < action_date <= T` | 检查主窗口唯一胜者是否已明显失效 | 只能否决，不得挑选候选 |
| 未来6个月前向样本外 | `T < action_date <= T+6个月` | 按冻结新版本真实交易并观察 | 不反向修改已冻结版本 |

三个历史窗口相互重叠、角色不能互换。最近2年和最近半年均是最近3年的子集，不是
独立样本外；它们不能参与候选搜索、排序，也不能在第一名失败后改选第二名。

#### 最近3年：筛选和排序规则

在每个半年节点，A、C、E、D都使用截至该节点的最近3年严格数据重新研究。该窗口
承担规则发现、候选比较和唯一排名；不能把最近2年或最近半年表现混入评分函数。

研究时继续锁定以下组合口径：

- 严格as-of，只使用信号时点可见的数据；
- 单账户逐笔机械复利；
- `A>C>E>D`真实开仓日资金占用顺序；
- 82.5%目标仓位；
- 费用、滑点、涨跌停、停牌和T+1规则；
- 一次只替换一条腿，另外三条腿冻结为本轮起始基线；
- 只有候选策略的独立单账户复利和逐腿替换后的总组合复利都严格提高，才允许修改
  该策略；否则保持旧规则。

D腿允许在半年节点把信号时点字段离散为固定因子值，并枚举多条`AND`条件分支。
每条分支必须先达到冻结的样本数、平均收益和胜率门槛，然后逐条独立替换当前D并
执行完整ACDE回放。只有D独立复利和ACDE总复利都提高的分支才进入最终排名，再取
ACDE复利最高的一条作为人工审核候选；全部条件`OR`只保留为诊断，不作为发布规则。
当前实现与结果见
[策略D半年多因子逐组合双门选优框架](strategy_d_factor_union_optimizer.md)。

所有候选必须从同一节点、同一3年窗口的不可变旧版本基线逐腿替换比较，禁止混用旧窗口
倍数、五年底座或其他资金口径。

#### 最近2年：近期必要确认

最近2年是最近3年主窗口的重叠子集，只用于确认主窗口唯一胜者在近期没有被旧行情
收益掩盖。候选的独立复利和只替换该腿后的组合复利都必须继续严格高于旧版本，样本
保留率、回撤恶化幅度和数据门禁也必须通过。

固定约束：

- 最近2年不得参与候选生成或候选排名；
- 主窗口第一名未通过近期确认时，本腿保持旧规则，不能改选第二名；
- 不得根据最近2年继续添加过滤条件或搜索参数；
- 必须明确披露它与主窗口重叠，不能称为独立样本外。

#### 最近半年：只做失效否决

最近半年也是主窗口的重叠子集，只检查主窗口唯一胜者是否已经出现明确失效迹象。
当前冻结失效条件同时考虑最低样本数、复利不高于1且平均收益不为正，以及最大回撤
下限。具体阈值必须写入节点配置并随结果封存，不能在看完结果后临时修改。

半年窗口只能对唯一胜者给出`PASS / FAIL / INSUFFICIENT_DATA`；`FAIL`使本腿保持旧规则，
`INSUFFICIENT_DATA`必须进入人工风险审核。它不能单独选参，也不能在第一名失败后改选
第二名。

#### 未来6个月：真正前向样本外与交易期

在节点`T`完成研究后，只有经人工确认并通过独立发布认证的候选，才能冻结新版本的
策略规则、配置、数据清单、代码哈希、组合顺序和认证结果。显式切换完成后，从`T`之后第一个
交易日起到下一更新节点的实际交易，才是新版本真正的前向样本外；未通过时继续运行旧版本。

要把这6个月称为真正前向样本外，必须同时满足：

- 第一个前向信号产生前已经完成版本冻结；
- 半年内不根据新出现的收益、回撤或候选修改策略参数；
- 每日候选、正式信号、组合选择、委托、成交和持仓结果完整留档；
- 费用、滑点、涨跌停、T+1和实际成交约束继续执行；
- 数据修复不得事后改写当日已经形成的候选结论；
- 实盘结果只描述已经发生的交易，不承诺未来收益。

研究候选只有在人工确认、独立冻结、发布认证和显式写入正式配置后，才能进入
下一个半年的实际使用期；否则继续运行旧版本。从实际切换后的第一个交易日到下一
更新节点，才是新版本真正的前向样本外；到下一节点时必须先封存这段表现。

### 4. 逐腿更新决策

本轮每条策略先形成研究结论；研究候选经人工审核和发布认证后，才允许形成
以下两种正式结论：

1. `UPDATE`：最近3年中，候选规则的独立策略复利严格高于旧规则，并且只替换该腿
   后的ACDE总组合复利也严格高于旧组合；最近2年两项复利继续严格提高，最近半年
   未触发失效否决，且样本、回撤、数据与风格门禁全部通过。
2. `KEEP_CURRENT`：上述任一条件不满足、数据不完整、口径不一致或无法严格复现，
   该策略保持不变。

最近2年确认或最近半年检查可以否决更新，但都不能把未在主窗口排名第一的候选变成
`UPDATE`，也不能触发补充搜索。
未完成人工审核或发布认证的数学胜者，只能标记为
`MANUAL_REVIEW_RESEARCH_CANDIDATE`，不得冒充`UPDATE`。

更新A、C、D、E时必须逐腿独立判断，不能用“A和E同时替换后的组合更高”掩盖其中
某一条腿单独替换后不增益。所有腿完成后，可以再报告同时应用全部通过项的组合结果，
但它不能替代逐腿门槛。

### 5. 半年循环与版本身份

每个版本按以下顺序流转：

```text
旧版本运行满本周期
    ↓
到达6月30日或12月31日
    ↓
先冻结旧版本本周期前向样本外账本
    ↓
最近3年主窗口滚动到当前节点并形成唯一排名
    ↓
逐腿研究ACDE并执行独立腿+总组合双复利门槛
    ↓
最近2年确认唯一胜者仍有增益
    ↓
最近半年只检查唯一胜者是否失效
    ↓
人工审核、独立冻结、发布认证和显式切换
    ↓
通过则未来6个月按新版本交易；未通过则继续旧版本
```

本周期刚完成的未来6个月，在下个节点会自然进入新的最近3年主窗口。这不等于
篡改上一版本的样本外结果：上一版本的账本已经永久封存；同一批日期只是从“上一版本
的前向评价数据”转为“下一轮滚动研究可使用的历史数据”，两种身份必须由版本号和
研究节点明确区分。

### 6. 永久样本外账本

每到更新节点，顺序必须是“先记旧账，再做新研究”。旧版本未完成封存时，不应启动
新一轮正式参数搜索。

每个版本的半年账本至少永久保留：

| 类别 | 必留字段 |
|---|---|
| 版本身份 | 发布编号、冻结时间、基线提交、配置/代码/输入哈希 |
| 时间口径 | 研究节点、最近3年主窗口、最近2年确认、最近半年失效检查、未来交易期 |
| 组合口径 | 腿序、仓位、费用、滑点、T+1、涨跌停和成交规则 |
| 分策略表现 | A/C/D/E各自样本数、胜率、平均/中位数收益、复利、最大回撤、盈亏比、最大盈亏、连续亏损 |
| 总组合表现 | 实际占仓笔数、逐笔复利、最大回撤、资金占用和分腿成交数 |
| 执行质量 | 候选覆盖率、计划数、委托数、成交率、部分成交、滑点、费用、无法买卖次数 |
| 数据质量 | 缺失日、未运行、未知状态、重复记录、回填记录和异常说明 |

永久保留的含义是：

- 新版本不得覆盖旧版本记录；
- 同一发布编号和同一半年节点重复生成时，内容一致只能幂等返回；
- 内容不一致必须报冲突，不能静默用新结果替换旧结果；
- 如发现历史记录错误，只能追加更正记录并保留原记录及更正原因；
- 账本、版本清单和摘要应进入版本控制及运行状态备份。

### 7. 节点示例

#### 2026年6月30日节点

| 角色 | 窗口 |
|---|---|
| 三年主优化 | `2023-07-01 <= action_date <= 2026-06-30` |
| 两年近期确认 | `2024-07-01 <= action_date <= 2026-06-30` |
| 最近半年失效检查 | `2026-01-01 <= action_date <= 2026-06-30` |
| 新版本前向交易 | `2026-06-30 < 信号日 <= 2026-12-31` |

主窗口负责候选排序；两年确认和半年检查均不得改变主窗口排序。三个历史窗口相互
重叠，不得把两年确认冒充独立样本外，也不得把半年检查单独用来选参数。

#### 2026年12月31日节点

| 角色 | 窗口 |
|---|---|
| 三年主优化 | `2024-01-01 <= action_date <= 2026-12-31` |
| 两年近期确认 | `2025-01-01 <= action_date <= 2026-12-31` |
| 最近半年失效检查 | `2026-07-01 <= action_date <= 2026-12-31` |
| 新版本前向交易 | `2026-12-31 < 信号日 <= 2027-06-30` |

具体落盘时按交易日历选取区间内实际交易日，不能用自然日缺少行情误报数据缺失。

### 8. 当前落地边界

三窗口研究入口和数据硬门禁已落地，但仍保持`research_only`：不会修改ACDE正式参数、
`A>C>E>D`、82.5%仓位、实盘开关、发布状态或券商流程。任何研究胜者仍须先展示完整
收益、回撤、增量样本和过拟合风险，再由人工决定是否进入独立冻结、前向验证与发布。

## 九、后续优化顺序

后续优化必须一次只解决一类问题，建议按以下顺序推进：

### 阶段一：候选、信号、资金裁决彻底分层

- 为ACDE定义统一、不可变的候选和正式信号结构；
- 每条策略独立记录是否完成计算、候选数量和第一名；
- 组合层只消费正式信号，不参与候选生成；
- 展示层只读取结果，不影响组合状态。

### 阶段二：拆分守护进程

- 数据流水线调度；
- 策略信号服务；
- 组合资金状态机；
- 订单执行与成交确认；
- 持仓恢复与审计播报。

每拆一层都必须保持现有行为回归一致，不能同时修改策略规则。

### 阶段三：强化数据血缘

- 为每日策略输入生成清单和哈希；
- 对关键字段建立跨数据源校验；
- 明确每个字段的最早可用时点；
- 把“0只候选”“未运行”“读取失败”“数据不完整”分别编码。

### 阶段四：补齐真实执行模型

- 集合竞价真实成交率；
- 09:30后分钟级滑点；
- 涨停排队与开板回封成交概率；
- 跌停延期卖出和尾盘容量；
- 不同资金规模下的成交覆盖率和冲击成本。

### 阶段五：冻结样本外与发布认证

- 冻结ACDE规则和配置哈希；
- 按每个自然月最后一个交易日执行月度更新；
- 最近3年作为唯一候选搜索和排序窗口；
- 更早历史数据只做风险诊断和数据核验，不得参与当月选参；
- 新版本冻结后的下一个自然月用于实际交易并积累真正前向样本外；
- 永久保留每个发布版本的月度样本外账本；
- 连续模拟盘验证；
- 达到发布标准后再讨论小资金实盘。

## 十、框架优化的验收规则

每一次框架优化都必须回答：

1. 修改的是数据、候选、组合、执行、持仓还是认证层？
2. 是否改变任何策略的入选股票或交易时点？
3. 是否改变`A>C>E>D`、82.5%仓位或单账户占仓？
4. 是否新增未来数据、乐观成交或资金重复使用？
5. 旧行为如何回归，新行为如何单测？
6. 是否需要重跑严格认证或刷新输入清单？
7. 失败时是否仍保持fail-closed？
8. 日志能否区分未知、未运行、0候选、计划、委托和成交？

如果一次修改同时改变策略条件、资金状态机和执行模型，应拆成多个独立阶段，分别
验证和提交，避免无法判断收益或风险变化来自哪里。

## 十二、当前结论

当前框架已经具备较完整的研究、组合资金、A股规则、订单安全和审计骨架。下一阶段
不应继续优先追求同窗口回测倍数，而应围绕以下三件事逐步提高系统质量：

```text
分层更清楚
真实成交证据更多
样本外发布标准更严格
```

本文作为后续框架优化的起点。每完成一个阶段，都应更新对应章节、测试证据和发布
状态，确保系统演进始终可解释、可回退、可复现。
