# 策略D半年多因子逐组合双门选优框架

> 首次落地：2026-08-24
> 当前决策窗口：2024-06-30～2026-06-30
> 当前正式D修改：否

## 一、目标

策略D把每次回封时已经知道的特征转换为固定因子值，枚举多个因子值的`AND`条件。
任何一条条件分支同时满足以下要求，就进入合格分支池：

```text
独立单账户实际执行笔数 >= 20
平均每笔账户收益 > 2%
胜率 > 55%
无法解析的退出 = 0
```

随后把每条合格条件分别作为一版候选D，逐条执行D独立占仓回放，并逐条替换回
`D>A>E>C`组合账户。只有D独立复利和ACDE总复利都严格高于当前正式版本的条件
才具备替换资格；在全部双门通过项中，按ACDE复利从高到低选择最佳单条件，交给
用户阅读完整报告后决定是否发布。全部达标条件`OR`仍计算，但只作为覆盖过宽的诊断。

## 二、参考脚本的继承与差异

参考文件`find_all_best_combo_historical.py`提供了三个可复用思想：

1. 先把原始指标变成可枚举因子；
2. 批量枚举多因子组合，不靠人工只试少数规则；
3. 把搜索结果转换为直接可执行的过滤条件。

D与加密小时策略的执行结构不同，不能直接复制矩阵乘法。D必须逐条处理首板身份、
回封信号先后、排队成交、14:55撤单、T+1、T+2退出和单账户占仓。因此每条D分支
都先选当日唯一信号，再做完整机械回放；不能用分组行收益冒充策略收益。

## 三、16个固定因子值

所有边界冻结在`src/strategy_d_factor_rules.py`，每半年只重新统计组合表现，不用收益
分位数反向改变因子边界。

| 因子 | 原始信号字段 | 主要因子值 |
|---|---|---|
| 回封时间 | `signal_hhmm` | 09:30～10:00、10:01～10:30、10:31～11:30、13点、14点前后 |
| 首封时间 | `first_seal_hhmm` | 与回封时间相同的固定时段 |
| 炸板次数 | `open_times_at_signal` | 1、2、3、4、5次以上 |
| 回封速度 | `last_break_to_signal_minutes` | 1分钟内、2～5、6～10、11～20、21分钟以上 |
| 首封至回封 | `first_to_signal_minutes` | 15分钟内、16～30、31～60、61～120、121分钟以上 |
| 上次封板维持 | `previous_seal_to_break_minutes` | 1分钟内、2～5、6～10、11分钟以上 |
| 炸板深度 | `last_break_close_depth_pct` | 0.2%内、0.2%～0.5%、0.5%～1%、1%～2%、2%以上 |
| 开盘涨幅 | `open_gap_pct` | 负值、0～3%、3%～7%、7%以上 |
| 信号前最低涨幅 | `pre_signal_min_return` | 负值、0～3%、3%～7%、7%以上 |
| 累计量能 | `signal_cumulative_amount_vs_prev_day` | 前日0.5倍内、0.5～1倍、1～1.5倍、1.5倍以上 |
| 市场累计触板数 | `market_ever_sealed_count` | 40以下、40～70、71～100、101～150、151以上 |
| 市场当前封住数 | `market_active_sealed_count` | 20以下、20～40、41～70、71～100、101以上 |
| 市场封住率 | `market_seal_rate` | 40%以下、40%～60%、60%～80%、80%以上 |
| 市场炸板事件率 | `market_break_event_rate` | 25%以下、25%～50%、50%～75%、75%以上 |
| 交易板块 | `market_segment` | 沪深主板、创业/科创、北交所 |
| 同板块封住率 | `same_segment_seal_rate` | 40%以下、40%～60%、60%～80%、80%以上 |

一分钟数据最终是否收涨停、信号后价格、队列确认、退出日和收益都不属于因子。

## 四、组合搜索与执行顺序

配置默认枚举一、二、三因子`AND`，共696组因子列组合。每组只遍历历史上实际出现
过的因子值组合。机械执行顺序固定为：

```text
固定两年窗口
→ 回封事件转换为因子值
→ 枚举1～3因子AND条件
→ 每条条件按最早回封、同分钟炸板2次优先、代码稳定排序
→ 后续价格穿透才确认排队成交
→ 独立单账户T+2回放
→ 筛选平均收益>2%、胜率>55%的全部分支
→ 每条达标分支逐个替换当前D
→ 每条分支重新执行D>A>E>C单账户组合回放
→ D独立复利和ACDE总复利都提高才进入最终排名
→ 在双门通过项中选择ACDE复利最高的单一条件
→ 生成完整TXT/JSON/CSV供人工决定
```

相同逐日选择序列仍会在诊断表中保留条件身份，便于审计；最终排名使用固定稳定排序。

## 六、发布与盘中执行

当前正式版本登记在：

```text
config/strategy_d_factor_release.json
```

正式文件目前是`LEGACY_FORMAL_D`，所以盘中监控继续执行既有2～3次炸板、14:00后
回封规则。未来若最佳单条件通过双复利门、用户阅读报告后再显式发布，文件切换为
`FACTOR_UNION`，
盘中监控会：

1. 从09:30持续维护完整首封、炸板、回封和市场状态；
2. 只在本轮新发生的真实回封时计算因子值；
3. 发布的最佳条件命中即进入D候选；
4. 继续强制首板、非ST、14:55前和可靠成交概率公共安全门；
5. 同一分钟优先炸板2次，再按代码稳定排序，每天只锁定一笔委托。

当日最早合格回封一旦被选中就消耗当天D机会；即使成交概率门失败或最终未成交，
也不能用事后结果补选更晚的回封信号。这与历史机械账本的未知队列阻断口径一致。

发布文件内容已加入D运行指纹；版本或条件变化后，旧盘中检查点自动失效，不能用旧
状态解释新规则。

## 七、半年运行命令

直接运行完整研究、不修改正式D：

```bash
cd /Users/user/Desktop/A_System
python3 scripts/optimize_strategy_d_factor_union.py
```

脚本自动选择不晚于运行日的最近一个6月30日或12月31日节点；2026-08-24运行时
自动选择`20260630`。运行完成后先查看：

```text
reports/strategy_d_factor_optimizer/20260630/best_dual_gate_profile.txt
```

也可以显式指定`--as-of 20261231`。脚本会自动完成达标条件逐个ACDE回放，不需要
再执行额外分析命令。如果目标窗口的数据账本尚未覆盖，脚本会直接失败，不会拿旧
窗口报告冒充新结果。

只有用户看完报告并明确决定更换时，才再次显式执行：

```bash
python3 scripts/optimize_strategy_d_factor_union.py \
  --as-of 20261231 \
  --apply
```

若最佳候选没有同时提高D和ACDE，即使传入`--apply`也只记录失败报告，不修改正式
版本。第一次普通运行绝不会修改正式D。
正式替换前会把旧发布文件归档到：

```text
config/strategy_d_factor_release_history/
```

输入事件账本必须先覆盖目标两年窗口；否则脚本fail-closed，不会拿旧窗口结果冒充
新半年更新。

## 八、输出文件

每个节点写入`reports/strategy_d_factor_optimizer/<YYYYMMDD>/`：

- `all_factor_profiles.csv`：全部支持充分的条件及完整指标；
- `qualified_factor_profiles.csv`：全部达到2%和55%的条件；
- `qualified_unique_profiles.csv`：按逐日选择序列去重；
- `all_profiles_acde_comparison.csv`：每条达标条件逐个替换D后的完整ACDE指标和双门结果；
- `best_dual_gate_profile.txt`：用户直接阅读的完整中文最佳结果；
- `best_dual_gate_profile.json`：同一最佳结果的机器可读版本；
- `candidate_d_detail.csv`：最佳条件的D逐日账户回放；
- `candidate_acde_detail.csv`：最佳条件替换后的ACDE逐日账户回放；
- `d_if_conditions.py.txt`：最佳条件的直接可读`if → allow_d`结构；
- `candidate_release.json`：仅包含最佳单条件的候选发布文件；
- `summary.json`：基线、最佳候选、双门禁和正式修改状态；
- `effective_or_profiles.csv`、`candidate_union_daily_picks.csv`：全部OR诊断，不用于发布。

机械复利只用于相同口径的版本比较，不代表未来收益或真实资金容量。
