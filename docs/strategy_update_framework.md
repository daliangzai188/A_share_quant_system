# 策略更新框架文档

最后更新：2026-08-22  
框架版本：`A_SYSTEM_STRATEGY_UPDATE_V1`  
当前状态：仅固化研究与更新规则，尚未把半年门禁和永久账本写入代码。

## 一、文档目的

本文固定A、C、D、E四条策略的半年更新方式。它解决的是“什么时候更新、使用哪段
数据做决定、旧版本如何评价、新版本从什么时候开始积累真正样本外”这四个问题，
不修改任何策略条件、排序、仓位、腿序或实盘开关。

本框架的核心不是把最近两年再拆成训练集和验证集，而是：

```text
每半年到达固定节点
    ↓
先封存旧版本过去半年的真实前向表现
    ↓
使用截至节点的最近24个月寻找并决定新规则
    ↓
用24个月之前的更早6个月做只读旁路验证
    ↓
冻结新版本
    ↓
在未来6个月按新版本交易并积累真正前向样本外
```

## 二、固定更新时间

每年只在以下两个自然日进入正式策略更新流程：

- `6月30日`
- `12月31日`

若节点日不是交易日，窗口仍以该自然日为截止日，数据取不晚于截止日的最后一个可用
交易日。不能因为短期回撤、连续亏损、行情突然变热或某个候选表现突出而在半年中途
重新调参。

半年内允许修复数据错误、程序缺陷和执行安全问题，但必须区分：

- **行为不变修复**：不改变历史候选、买卖日期、仓位和资金顺序，可按工程流程修复；
- **策略行为变化**：会改变候选、排序、过滤、持有期、腿序或仓位，只能进入下一个
  `6月30日/12月31日`更新节点评审。

## 三、三个时间窗口

设本轮更新时间为`T`，三个窗口严格定义如下：

| 窗口 | 日期范围 | 用途 | 是否影响本轮策略决策 |
|---|---|---|---|
| 更早6个月旁路验证 | `T-30个月 <= 信号日 < T-24个月` | 检查新规则在更早市场环境中的稳定性 | 否 |
| 最近24个月决策窗口 | `T-24个月 <= 信号日 <= T` | 寻找规则、比较候选、决定是否更新 | 是，且是唯一决策窗口 |
| 未来6个月前向样本外 | `T < 信号日 <= T+6个月` | 按冻结新版本真实交易并观察 | 不反向修改已冻结版本 |

三个窗口的角色不能互换，也不能把最近24个月改成“前18个月寻找规则、后6个月决定
是否通过”。最近24个月是一个完整的滚动决策窗口，全部用于寻找并决定当下最佳策略。

### 1. 最近24个月：寻找和决定规则

在每个半年节点，A、C、D、E都使用截至该节点的最近24个月严格数据重新研究。该窗口
同时承担规则发现和本轮策略决策，不额外从其中扣出6个月作为否决型验证集。

研究时继续锁定以下组合口径：

- 严格as-of，只使用信号时点可见的数据；
- 单账户逐笔机械复利；
- `D>A>E>C`资金占用顺序；
- 82.5%目标仓位；
- 费用、滑点、涨跌停、停牌和T+1规则；
- 一次只替换一条腿，另外三条腿冻结为本轮起始基线；
- 只有候选策略的独立单账户复利和逐腿替换后的总组合复利都严格提高，才允许修改
  该策略；否则保持旧规则。

所有候选必须从同一节点、同一24个月窗口的旧版本基线逐腿替换比较，禁止混用旧窗口
倍数、五年底座或其他资金口径。

### 2. 更早6个月：只读旁路验证

最近24个月之前的更早6个月用于观察规则跨市场阶段的表现，但它不是本轮策略决策
窗口，也不能改变最近24个月已经得出的选择。

该窗口只回答：

- 新规则放到更早一段行情中，交易方向是否明显异常；
- 收益是否完全依赖最近24个月中的单一行情阶段；
- 回撤、连续亏损、盈亏比和成交可行性是否暴露额外风险；
- 是否需要在报告中提高风险提示或降低对研究结论的信心。

固定约束：

- 旁路结果不能否决最近24个月的双复利决策；
- 旁路结果不能触发继续调参、增加过滤条件或回到24个月窗口重新搜索；
- 不能挑选更早6个月中表现好的参数替换本轮结果；
- 必须原样披露正面和负面结果。

因为规则是在时间上更晚的24个月数据中找到，再回放到更早6个月，所以这段只能称为
**更早历史旁路验证**，不能冒充真正的前向样本外。它的价值是补充稳健性观察，而不是
取得发布资格或预测未来收益。

### 3. 未来6个月：真正前向样本外与交易期

在节点`T`完成研究后，必须先冻结新版本的策略规则、配置、数据清单、代码哈希、组合
顺序和认证结果。冻结完成后，从`T`之后第一个交易日起到下一更新节点，按该版本进行
实际交易；这未来6个月才是本版本真正的前向样本外。

要把这6个月称为真正前向样本外，必须同时满足：

- 第一个前向信号产生前已经完成版本冻结；
- 半年内不根据新出现的收益、回撤或候选修改策略参数；
- 每日候选、正式信号、组合选择、委托、成交和持仓结果完整留档；
- 费用、滑点、涨跌停、T+1和实际成交约束继续执行；
- 数据修复不得事后改写当日已经形成的候选结论；
- 实盘结果只描述已经发生的交易，不承诺未来收益。

未来6个月是新策略的实际使用期，不是等待验证结束后才启用策略。也就是说，本轮按
最近24个月得到的最新最佳版本会在下一半年直接投入受现有认证、风控和资金限制约束
的交易；到下一个更新节点，再先封存这段表现。

## 四、半年循环关系

每个版本按以下顺序流转：

```text
旧版本运行满本周期
    ↓
到达6月30日或12月31日
    ↓
先冻结旧版本本周期前向样本外账本
    ↓
最近24个月滚动到当前节点
    ↓
逐腿研究ACDE并执行独立腿+总组合双复利门槛
    ↓
更早6个月只读旁路回放并披露风险
    ↓
冻结新版本身份和全部口径
    ↓
未来6个月按新版本交易
```

本周期刚完成的未来6个月，在下个节点会自然进入新的最近24个月决策窗口。这不等于
篡改上一版本的样本外结果：上一版本的账本已经永久封存；同一批日期只是从“上一版本
的前向评价数据”转为“下一轮滚动研究可使用的历史数据”，两种身份必须由版本号和
研究节点明确区分。

## 五、版本冻结与永久账本

每到更新节点，顺序必须是“先记旧账，再做新研究”。旧版本未完成封存时，不应启动
新一轮正式参数搜索。

每个版本的半年账本至少永久保留：

| 类别 | 必留字段 |
|---|---|
| 版本身份 | 发布编号、冻结时间、基线提交、配置/代码/输入哈希 |
| 时间口径 | 研究节点、最近24个月窗口、更早6个月窗口、未来交易期 |
| 组合口径 | 腿序、仓位、费用、滑点、T+1、涨跌停和成交规则 |
| 分策略表现 | A/C/D/E各自样本数、胜率、平均/中位数收益、复利、最大回撤、盈亏比、最大盈亏、连续亏损 |
| 总组合表现 | 实际占仓笔数、逐笔复利、最大回撤、资金占用和分腿成交数 |
| 执行质量 | 候选覆盖率、计划数、委托数、成交率、部分成交、滑点、费用、无法买卖次数 |
| 数据质量 | 缺失日、未运行、未知状态、重复记录、回填记录和异常说明 |

永久保留的含义是：

- 新版本不得覆盖旧版本记录；
- 同一发布编号和同一半年节点重复生成时，内容一致只能幂等返回；
- 内容不一致必须报冲突，不能静默用新结果替换旧结果；
- 如发现历史记录错误，只能追加更正记录并保留原记录及更正原因；
- 账本、版本清单和摘要应进入版本控制及运行状态备份。

## 六、每个节点的决策规则

本轮每条策略只允许出现两种正式结论：

1. `UPDATE`：最近24个月中，候选规则的独立策略复利严格高于旧规则，并且只替换该腿
   后的ACDE总组合复利也严格高于旧组合；全部严格口径一致。
2. `KEEP_CURRENT`：上述任一条件不满足、数据不完整、口径不一致或无法严格复现，
   该策略保持不变。

更早6个月的旁路验证单独给出`STABLE / RISK_WARNING / INSUFFICIENT_DATA`，只影响
风险说明，不把`UPDATE`改成`KEEP_CURRENT`，也不把`KEEP_CURRENT`改成`UPDATE`。

更新A、C、D、E时必须逐腿独立判断，不能用“A和E同时替换后的组合更高”掩盖其中
某一条腿单独替换后不增益。所有腿完成后，可以再报告同时应用全部通过项的组合结果，
但它不能替代逐腿门槛。

### 2026年6月30日节点

| 角色 | 窗口 |
|---|---|
| 更早6个月旁路验证 | `2023-12-30 <= 信号日 < 2024-06-30` |
| 最近24个月决策 | `2024-06-30 <= 信号日 <= 2026-06-30` |
| 新版本前向交易 | `2026-06-30 < 信号日 <= 2026-12-31` |

寻找规则和6个月否决型验证。

### 2026年12月31日节点

| 角色 | 窗口 |
|---|---|
| 更早6个月旁路验证 | `2024-06-30 <= 信号日 < 2024-12-31` |
| 最近24个月决策 | `2024-12-31 <= 信号日 <= 2026-12-31` |
| 新版本前向交易 | `2026-12-31 < 信号日 <= 2027-06-30` |

具体落盘时按交易日历选取区间内实际交易日，不能用自然日缺少行情误报数据缺失。
