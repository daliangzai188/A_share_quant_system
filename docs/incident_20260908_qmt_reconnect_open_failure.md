# 2026-09-08 QMT重连自锁导致A策略开仓失败

## 结论

当日策略信号、A>C>E>D互斥顺序和计划生成均正常。开仓失败的直接原因是QMT不可用；
更深层根因是运行中重连状态机存在自退避缺陷：第3轮完整扫描只打印了日志，实际在
执行前就被同一轮刚设置的退避截止时间拒绝，导致备用session永远没有机会恢复连接。

本次属于执行安全缺陷修复，不修改候选、阈值、排序、退出、腿序、仓位、费用、滑点、
T+1、涨跌停或成交规则。固定腿序仍为A>C>E>D。

## 修复内容

文件：`scripts/trading_daemon.py`

- 方法：`_qmt_query_account_positions`
  - 对明确的QMT账户/持仓只读空返回，保留当前持久连接并在原会话复查1次。
  - 账务不一致和非法结构不重试、不放宽，继续fail-closed。
- 方法：`_qmt_get_raw`
  - 把第3次真实建连统一升级为完整备用path/session扫描，消除业务层二次调用被自身退避
    拒绝的问题。
- 方法：`_qmt_connect`
  - 完整扫描只创建一个adapter，并从上次成功path/session开始遍历；避免先创建失败的
    缓存对象，再创建第二个对象干扰QMT底层资源。
- 方法：`_print_account_status`
  - 冷连接本轮已经失败时不立即二次调用；等待下一次真实连接机会。
  - 交易关键窗口连续建连失败时触发干净进程恢复。
- 方法：`_request_qmt_reconnect_stalled_recovery`
  - 完整扫描仍失败后，用专用退出码92停止当前交易进程；keeper拉起新进程后先执行
    委托、成交和持仓对账。
- 方法：`write_broker_health`
  - 健康文件改用唯一临时名；对Windows共享冲突做3次、每次50毫秒的有限重试并清理
    临时文件。

文件：`tests/test_broker_maintenance_recovery.py`

- 新增瞬时空返回原会话复查测试。
- 新增第3次真实连接升级完整扫描测试。
- 新增完整扫描只创建一个adapter测试。
- 新增冷连接失败不在同轮自退避测试。
- 新增连续失败请求进程恢复测试。
- 新增Windows健康文件共享冲突重试测试。
