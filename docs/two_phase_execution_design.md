# 两段式开仓执行引擎设计(竞价 + POV 贪心前置平滑)

> 2026-07-15 立项(用户拍板)。目标:15 万 → 1000 万全程适用的开仓执行架构,
> 小资金阶段零损耗(行为与现状完全一致),大资金阶段自动激活流动性保护。
> 状态:**2026-07-16 已落地实盘(commit 2cda523)**——POV引擎入 trading_daemon.py
> (竞价段拆分/平滑worker/09:30补买互斥/断点恢复/撤买单白名单修复),
> config.live_trade.pov_* 六键,pov_enabled=true。逐片执行记录 reports/pov_execution_log.csv,
> 用于上线后滚动校准竞价占比/首片占比参数。

## 一、三层限额结构

```
普通空仓日 actual_target = min( 09:20权益快照 × max_total_position_pct(82.5%),
                       权益 × max_position_pct(85%单票硬顶),
                       信号日成交额 × total_liquidity_cap_pct(2%),    ← 风险硬顶
                       max_single_order_amount(>0 时) )

任何买单 hard_cap = min(09:20权益快照×85%, 当前QMT权益×85%,
                         QMT可用现金-缓冲, 退出容量硬顶, 固定单笔硬顶)

旧策略仓未清空 = 禁止生成和提交新买单（含今日到期、逾期、sell_pending）

竞价段限额 auction_cap = 信号日成交额 × auction_share_est(1%) × auction_participation(10%)
                       = 信号日成交额 × 0.1%
```

- **取消衔接开仓（2026-08-03）**：只要券商仍实际持有本系统旧策略仓，早盘
  不开新仓；打新中签股票/债券、人工持仓没有本地策略身份，不触发阻断。
  D策略接力是唯一独立流程：09:23只卖虚拟匹配量可安全承接的部分，09:30后
  按“卖D确认一片、用该片实际释放资金买候选一片”的成对POV执行，不要求先清空D；
  原有空闲现金不参与接力，D面对L仍不接力；
- **auction_share_est = 1%**:竞价占信号日成交额的估计,来源=83 笔买入日 1 分钟
  数据剥离法实测中位 1.05%(research_buy_auction_1m.csv);上线后每笔实盘自动
  回写实测值,滚动校准;
- **auction_participation = 10%**:竞价参与率红线(与 E2 现行口径一致);
- **total_liquidity_cap_pct = 2%**(2026-07-16 买卖全链重放定稿):当日合并开仓
  ≤ 信号日成交额 × 2%。80笔两端真实分钟价重放:1000万起单轮 1%=3.13x /
  2%=3.68x / 3%=3.78x / 5%=3.80x——2%拿到增益大头,且卖出端跑道用满率仅29%
  (下午容量≈sig×7%)缓冲厚;16万/100万各档取值无差;到1000万路径亦零代价
  (第200笔)。缺少信号日成交额时 `liquidity_cap_fail_closed=true` 直接拒绝
  开仓。千万级仓位因此要求信号日成交额≥4.75亿元;
- 全部参数入 config.live_trade,可调。

## 二、执行状态机(单标的开仓日)

```
09:20  挂涨停价买单,最坏委托额≤hard_cap              ── 竞价排队
09:25  竞价撮合,记录实际成交金额 actual_filled_1
09:30  统一重算 remain = actual_target - actual_filled_1
       remain ≤ 0 → 完成,绝不补仓
       原计划未触发POV → 也进入既有POV框架补实际金额差
       原计划已触发POV → 把竞价实际差额合并进POV并重新分配各片金额
09:30~10:30  平滑段 = POV贪心前置(2026-07-16 三因子网格终版定稿):
       每 5 分钟一片,片金额 = min(remain, 85%硬顶剩余,
                                     QMT实时可用现金-缓冲,
                                     上一片实测成交额 × 10%)
       (第一片预算基数 = 信号日成交额 × 18%,即"9:30-9:35成交/信号日成交"
        的 25 分位实测保守值,中位实为 23.6%——动量票开盘量爆炸)
       每片用真实委托价折算股数；累计实际成交达到82.5%即停；
       10:30 收口,低于80%明确告警但不突破追价/流动性保护强买。
       三因子(片数/间隔/权重)不再是自由参数:片数与窗口由参与率红线自动导出,
       量大的票 1-2 片买完(≈现状),薄票自动拉长。回放:因果POV(无前视)
       第200笔到1000万 = 打平零冲击理想,完成率100%,90%的笔 9:40 前买完;
       对比 12片VWAP=216笔、12片均分TWAP=222笔(强制铺满60分钟窗口是
       机构隐藏意图的设计,不是我们的目标,拖到10点后的片全是高价片);
       红线 5%/10%/15% 结果完全相同 → 取保守 10%(与E2竞价红线同口径,免费)
       挂单价 = min(买一价+0.01, 开盘价×(1+chase_cap 2%))   ← 追价保护
       90 秒未成交 → 状态判定撤单 → 下一片重算
       盘中触涨停 → 暂停平滑(涨停不追,回测口径一致);打开后恢复
10:30  收口:未完成部分放弃当日不再追,记录完成率+均价 vs 开盘价偏离
```

## 三、风控与口径约束

1. **买入均价保护**:平滑段挂单价不高于开盘价 × 1.02(chase_cap)——两段合成
   均价对回测口径(开盘价)的最大偏离被锁死在 +2% × 平滑段占比;
2. **完成率妥协原则**:宁可仓位不满,不追高破坏口径(与"涨停不买"同哲学);
3. 每片撤单用状态判定(2026-07-10 口径),置于 14:40 撤买单与平仓时序之外
   (平滑段 10:30 前结束,与尾盘链路零交叠);
4. **竞价残单互斥**:09:30撤销未终态竞价残单并再次确认；终态不明确时POV
   fail-closed暂停，避免竞价残单与POV同时成交后突破85%;
5. 执行记录逐片落盘:实测竞价占比、各片成交价、完成率——自动校准参数,
   并为回测口径重校准积累数据。

## 四、激活阈值(向后兼容的关键)

target ≤ auction_cap 时状态机在 09:25 结束,行为与现行架构完全相同。
中位票(12.7 亿)auction_cap ≈ 127 万 → 账户约154万(82.5%≈127万)以下通常隐身。
偏薄票提前激活(天顺类 0.7 亿 → auction_cap=7万,现在就会分段)——这正是
保护的本意:薄票才需要平滑。

## 五、验证与上线路径

1. **回放验证(2026-07-16 已完成,真实5分钟价格,83笔近一年样本)**:
   压力场景=目标仓位顶格(信号日成交额×10%):
   - 逆向选择实锤:大肉笔(net>10%)完成率仅51%(通过3.9/12片),亏损笔88%
     (9.9片)——涨的日子买不进,跌的日子满仓,用户预判正确;
   - 但总账可承受:亏损日平滑均价比开盘价便宜-1.56%(高开回落),部分对冲;
     复利16万→1000万:理想开盘价满仓(无冲击)第200笔,两段式实测第222笔,
     **真实成本=慢22笔≈0.21%/笔**;一把梭真实冲击只要>0.21%/笔两段式即赢
     (千万级挂单为竞价额数十倍,物理上必然远超);
   - 重放自洽性:平滑段单片参与率中位最大值仅2%(超100%仅1笔)→"我们的单
     不改变历史价格"假设成立;
   - chase_cap扫描:+2%与+3%、不设限同为222笔,+5%反而253笔(追高成本≈
     踏空成本,中间地带两头不讨好)→ **保留2%**(有保护且零额外成本);
   - 数据:research_buy_smooth_5m.csv(买入日09:30-10:30,5m),片成交价=
     片起点价(上根bar收盘代理,首片=开盘价);
2. **灰度**:影子模式(只算不下单,日志对比)≥3 个交易日 → 实盘;
3. 明确不做:下午追仓、跨日补仓、市价单。

## 六、与现有组件的关系

- E2 竞价动态限仓(竞价×10%):被本引擎吸收统一(E2 的 auction_cap 同款);
- 单笔限额(0=不限):第一层 min 保留，由82.5%目标仓位+85%单票硬顶接管;
- 卖出端采用独立安全POV：13:00起按实时外部流量和盘口深度拆单，14:53撤单
  交权，14:55按QMT实际余量主平仓，14:56:20起撤未成系统单并复核，14:57:05仅以
  真实残仓进入收盘集合竞价兜底。入场/当前参考市值≥950万元且信号日成交额
  ≥4.75亿元(与2%开仓硬顶自洽)时固定14:15建立跑道；小仓位仍走动态门禁。该千万级分组只有17笔
  （后段验证8笔），属于容量保护，不是成交或收益保证。
- 全部自动卖单共用 `data/processed/exit_execution_state.json` 安全账本：首单前
  固化当日退出目标和非目标仓保护底线，下单前先原子写 `PREPARED` intent。
  QMT暂时查不到订单、撤单交接未明确成功、同代码存在人工卖单或持仓归属不一致
  时均 fail-closed，未知数量按全量占用，防止daemon重启/成交回报延迟后重复卖出。
