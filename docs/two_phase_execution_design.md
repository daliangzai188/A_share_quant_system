# 两段式开仓执行引擎设计(竞价 + 盘中平滑)

> 2026-07-15 立项(用户拍板)。目标:15 万 → 1000 万全程适用的开仓执行架构,
> 小资金阶段零损耗(行为与现状完全一致),大资金阶段自动激活流动性保护。
> 状态:设计定稿,待实现(周末)+ 回放验证 + 灰度上线。

## 一、三层限额结构

```
目标仓位 target = min( 权益 × max_position_pct(80%),
                       信号日成交额 × total_liquidity_cap_pct(10%),   ← 硬顶
                       max_single_order_amount(>0 时) )

竞价段限额 auction_cap = 信号日成交额 × auction_share_est(1%) × auction_participation(10%)
                       = 信号日成交额 × 0.1%
```

- **auction_share_est = 1%**:竞价占信号日成交额的估计,来源=83 笔买入日 1 分钟
  数据剥离法实测中位 1.05%(research_buy_auction_1m.csv);上线后每笔实盘自动
  回写实测值,滚动校准;
- **auction_participation = 10%**:竞价参与率红线(与 E2 现行口径一致);
- **total_liquidity_cap_pct = 10%**:当日合并开仓 ≤ 信号日成交额 × 10%,
  无论平滑与否的绝对硬顶(极端情况的最后防线);
- 全部参数入 config.live_trade,可调。

## 二、执行状态机(单标的开仓日)

```
09:15  挂涨停价买单,金额 = min(target, auction_cap)     ── 与现状同款,竞价排队
09:25  竞价撮合,记录已成交 filled_1
09:30  剩余 remain = target - filled_1
       remain ≤ 0 → 完成,状态机结束(小资金阶段永远在这里结束)
09:30~10:30  平滑段:12 片 × 5 分钟
       每片金额 = remain / 剩余片数
       挂单价 = min(买一价+0.01, 开盘价×(1+chase_cap 2%))   ← 追价保护
       90 秒未成交 → 状态判定撤单 → 下一片重算
       盘中触涨停 → 暂停平滑(涨停不追,回测口径一致);打开后恢复
10:30  收口:未完成部分放弃当日不再追,记录完成率+均价 vs 开盘价偏离
```

## 三、风控与口径约束

1. **买入均价保护**:平滑段挂单价不高于开盘价 × 1.02(chase_cap)——两段合成
   均价对回测口径(开盘价)的最大偏离被锁死在 +2% × 平滑段占比;
2. **完成率妥协原则**:宁可仓位不满,不追高破坏口径(与"涨停不买"同哲学);
3. 每片撤单用状态判定(2026-07-10 口径),置于 14:40 撤买单与平仓时序之外
   (平滑段 10:30 前结束,与尾盘链路零交叠);
4. 执行记录逐片落盘:实测竞价占比、各片成交价、完成率——自动校准参数,
   并为回测口径重校准积累数据。

## 四、激活阈值(向后兼容的关键)

target ≤ auction_cap 时状态机在 09:25 结束,行为与现行架构完全相同。
中位票(12.7 亿)auction_cap ≈ 127 万 → 账户 ~160 万(80%=128万)以下全程隐身。
偏薄票提前激活(天顺类 0.7 亿 → auction_cap=7万,现在就会分段)——这正是
保护的本意:薄票才需要平滑。

## 五、验证与上线路径

1. **回放验证(实现后)**:QMT 拉 199 笔买入日全天 5 分钟数据,重放两段式执行,
   对比"开盘价一把梭"的复利差异;chase_cap/片数参数网格;
   预期:早盘高开回落结构(卖出日实测开盘过冲 -0.86%)下,平滑段均价可能
   优于开盘价,复利影响approximately中性偏正,待数据确认;
2. **灰度**:影子模式(只算不下单,日志对比)≥3 个交易日 → 实盘;
3. 明确不做:下午追仓、跨日补仓、市价单。

## 六、与现有组件的关系

- E2 竞价动态限仓(竞价×10%):被本引擎吸收统一(E2 的 auction_cap 同款);
- 单笔限额(0=不限):第一层 min 保留,月底切 0 后由 80%+硬顶接管;
- 卖出端不变(14:55 独占平仓+逃生舱,与本设计无交叠)。
